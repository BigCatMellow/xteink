## Emergence pass

Sources compared: [repository handoff](../../HANDOFF.md), which distinguishes
SD filesystem deployment from physical launch proof, and the current MAPS
Task Lifecycle's user-acquired release-path and operational-independence checks.

- **Insight:** a shell can pass host navigation and packaging checks while its
  actual entry/recovery path remains unproved.
- **Synthesis mechanism:** both sources distinguish artifact correctness from
  the user's acquisition/launch path. Applying that distinction to shell scope
  makes startup and recovery separate acceptance conditions.
- **Value:** avoids presenting a manually launched app as an automatic stock
  launcher or making recovery depend on the original development session.
- **Smallest test/falsifier:** an authorized, reversible device probe records
  the exact cold/wake/entry sequence and demonstrates the exit/recovery path.
  Inability to enter through the claimed route falsifies that route's claim.
- **Promotion, 2026-11-08:** recommendation to the roadmap owner: make explicit
  entry behavior and recovery evidence acceptance conditions for the selected
  route. This receipt authorizes no probe or implementation. The parent
  roadmap/task owns disposition and execution authority.

Other candidate: automatically opening the shell after sleep. **Incubating,
pass 1:** no verified firmware hook or user-experience evidence yet; revisit
after startup/resume research. Do not silently turn this idea into required work.
